O que mexer no Starchats (.env) para aguentar carga

No Starchats, os 3 knobs que mais importam são: WEB_CONCURRENCY, RAILS_MAX_THREADS e SIDEKIQ_CONCURRENCY (e o pool de conexão do banco precisa acompanhar). 
Starchats Docs

Exemplo de base (ajuste conforme CPU/DB):

# Rails/Puma
WEB_CONCURRENCY=2
RAILS_MAX_THREADS=10

# Sidekiq (se você ainda tiver 1 worker único)
SIDEKIQ_CONCURRENCY=25

# Redis / Postgres
REDIS_URL=redis://redis:6379
DATABASE_URL=postgresql://postgres:senha@postgres:5432/chatwoot_production


Referência de DATABASE_URL/REDIS_URL e padrão do .env no Starchats.

Regra prática pro seu caso: um Sidekiq “realtime” só pra filas críticas (webhook/whatsapp/send) e outro(s) pra jobs pesados (SLA, e-mail, rotinas).

2) Implementação (docker-compose): múltiplos serviços Sidekiq

Você duplica o serviço sidekiq e muda command/concurrency/queues. Exemplo (modelo):

services:
  # ... rails/postgres/redis etc

  sidekiq_realtime:
    image: starchats/starchats:latest
    env_file: .env
    depends_on: [postgres, redis]
    environment:
      - RAILS_ENV=production
      - NODE_ENV=production
    command: ["bundle","exec","sidekiq","-c","30","-q","critical,4","-q","default,2"]

  sidekiq_sla:
    image: starchats/starchats:latest
    env_file: .env
    depends_on: [postgres, redis]
    environment:
      - RAILS_ENV=production
      - NODE_ENV=production
    command: ["bundle","exec","sidekiq","-c","5","-q","low","-q","default"]


Pontos importantes:

Weights: critical,4 faz a fila critical ser checada mais vezes. 
GitHub

Se você precisa critical estrita e ainda quer weights nas outras, a própria wiki recomenda processo dedicado pra critical. 
GitHub

Evite “dezenas de filas” no mesmo processo (vira pancadaria no Redis). 
GitHub

O compose padrão do Starchats roda Sidekiq apontando para config/sidekiq.yml (você pode manter isso e ainda assim criar processos adicionais com -q). 
GitHub

Checklist rápido “entre outros componentes”

Banco (Postgres): seu pool precisa bater com threads/processos (senão vira gargalo e dá latência). O próprio Starchats fala do ajuste de pool vs threads/processos. 
Starchats Docs

Redis: mantenha Redis “saudável” (latência baixa) porque Sidekiq depende dele e o Starchats usa REDIS_URL. 
Starchats Docs

Proxy (Nginx): o guia oficial lembra que, por padrão, os containers ficam no localhost e você deve colocar Nginx na frente. 
Starchats Docs

Evolution / WhatsApp: 100 msg/s é carga alta; dependendo do canal, existe limite/throughput do próprio provedor. (Como referência, a própria Meta cita números de throughput em cenários de on-premises da plataforma do WhatsApp.)
